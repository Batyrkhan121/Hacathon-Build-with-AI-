# Как Qadam использует данные и генерацию (RAG)

Принцип: **факты считает код, Claude только объясняет.** Модель видит лишь отобранных кандидатов. Расстояния, минуты пешком и часы работы она не пишет: их подставляет код.

## Схема
```
запрос + ориентир / H3-ячейка + время
        │
1. понять запрос ──── Claude (JSON по схеме) ─ сбой ─► правила по ключевым словам
2. контекст ───────── центр ячейки, время UTC+5, погода Open-Meteo, радиус
3. фильтры ────────── расстояние, часы, дети, коляска, помещение, ночь
4. поиск по смыслу ── эмбеддинги Gemini (если есть ключ) или лексика
5. ранжирование ───── близость, часы, погода, полнота данных → top-8
6. ответ ──────────── Claude пишет «почему / что делать» ─ сбой ─► шаблоны
        │
   проверка: id из кандидатов, факты из данных, «открыто сейчас» только при open/high
        │
   1–3 карточки + мини-маршрут + «Какие данные использованы»
```

## Шаги
1. **Понять запрос.** Текст превращается в намерение: категории, теги, бюджет времени, дети, коляска, ночь, турист, язык. Сначала пробуем Claude (`claude-sonnet-5-5`, запасная модель `claude-haiku-5-5`). При сбое работают правила по ключевым словам на ru, kk и en. Явные фильтры из интерфейса важнее того, что извлечено из текста.
2. **Учесть контекст.** Местное время UTC+5, погода из Open-Meteo (кэш 15 минут; если погода недоступна, работаем без неё), радиус поиска по бюджету времени.
3. **Отфильтровать по правилам.** Отсекаем дальние места, закрытые сейчас, неподходящие детям (бары, клубы). Ночью оставляем только места, которые подтверждённо работают допоздна.
4. **Найти похожее по смыслу.** Если задан `GEMINI_API_KEY`, сравниваем эмбеддинг запроса с индексом POI (numpy, косинус). Без ключа считаем лексическую близость по названиям, тегам и словарю синонимов. У Anthropic нет API эмбеддингов, поэтому этот шаг необязательный.
5. **Ранжировать.** Итоговый скор складывается из частей: релевантность 0,45, близость 0,20, часы 0,15, популярность 0,10, полнота данных 0,05, погода 0,05. Затем MMR (λ = 0,7) убирает однотипные места из топ-3.
6. **Сформулировать ответ.** Claude получает кандидатов и пишет «почему» (не больше двух предложений) и «что делать». Текст пользователя передаётся модели как данные, а не как инструкции.

## Проверка после генерации
- Карточка с id не из списка кандидатов отбрасывается.
- Название, категорию, расстояние, минуты пешком, часы и адрес берём из данных, а не из ответа модели.
- Фразы «открыто сейчас», «open now», «қазір ашық» удаляются, если статус часов не open с уверенностью high.
- Метки: `idea_source` (poi_data или generated), `facts_sources` (osm, wikidata и т. д.), `open_confidence`.

## Запасной путь без LLM
`use_llm=false`, отсутствие ключа, лимит, отказ или таймаут приводят к одному результату: разбор запроса правилами и шаблонные карточки по тем же кандидатам. В панели данных это видно как `generation: template`. Сценарий E10 в eval проверяет этот путь.

## Данные
OpenStreetMap через Overpass: 531 POI в пяти демо-зонах на 18.10, выгрузка автоматизирована (`pipeline/`). Обогащение через Wikidata. Подробности и полнота полей: docs/DATA.md (дорожка DATA).

Статус на 18.10: шаги 1–6 и проверка написаны в ветках дорожек CORE и LLM, сквозной `app/pipeline.recommend` в работе. Пока шаги не влиты в `main`, это описание кода в ветках.
