# Как Qadam соединяет данные и генерацию (RAG)

Принцип: **факты считает код, Claude только объясняет.** Модель видит лишь отобранных кандидатов. Расстояния, время пешком и часы работы в карточку подставляет код.

```
запрос + ориентир / H3-ячейка + время
  │
  1 понять запрос ──── Claude, JSON по схеме ── сбой ──► правила ru/kk/en
  2 контекст ───────── центр ячейки, время UTC+5, погода, радиус
  3 фильтры ────────── расстояние, часы, дети, коляска, помещение, ночь
  4 релевантность ──── эмбеддинги (Gemini через OpenRouter); нет вектора → лексика
  5 ранжирование ───── веса + MMR → top-8 кандидатов
  6 текст ──────────── Claude: «почему / что делать» ── сбой ──► шаблоны
  │
  проверка ─► 1–3 карточки + мини-маршрут + «Какие данные использованы»
```

## Данные (в `main`)
- **Источник.** OpenStreetMap через Overpass, сбор одной командой `python -m pipeline.run_all`: зеркала, повторы, кэш. Подробнее в `docs/DATA.md`.
- **Объём на 18.10:** 1222 POI по всей Астане. Часы работы есть у 28% мест, доступность для коляски указана у 5%. Плотность неравномерная: например, у аэропорта всего 3 кафе.
- **Обогащение:** описания из Wikidata и короткие описания от Claude с меткой `llm_generated`. В текущем снимке описание есть у 3% мест (40 из 1222): 37 от Claude (метка `llm_generated`, только для заметных мест: музеи, парки, памятники и т. п.), по одному из Wikidata, OSM и ручной правки.
- **Индекс эмбеддингов** (`data/index/`): `google/gemini-embedding-001` через OpenRouter, 1222 × 768, собран 18.10 в 20:26, статус ok. Запрос получает вектор той же моделью. Если вектор не получен (нет ключа или OpenRouter недоступен), релевантность считается по словам. Если Claude доступен, он выбирает из 16 кандидатов («поиск: по словам, отбор — Claude»); без ИИ берутся top-8 и шаблонные карточки.

## Шаги
1. **Понять запрос** (`app/query_parser.py`). Claude `claude-sonnet-5-5` (запасная модель `claude-haiku-5-5`) возвращает `QueryIntent`. При сбое работают правила по ключевым словам. Фильтры из интерфейса важнее того, что извлечено из текста.
2. **Учесть контекст** (`app/geo.py`, `app/hours.py`, `app/weather.py`). Поиск идёт от центра ячейки или ориентира. Время всегда UTC+5. Погода берётся из Open-Meteo с кэшем на 15 минут; если она недоступна, работаем без неё.
3. **Отфильтровать** (`app/retrieval.py`). Отсекаются дальние места и закрытые сейчас. С ребёнком не попадают бары и клубы. Ночью остаются только места, открытые по данным с уверенностью high или с тегами `late_open`/`24_7`. Тег `night` (тип заведения: бар, клуб) без часов фильтр не проходит.
4. **Оценить релевантность.** Если есть индекс, используется косинус по эмбеддингам. Без индекса — лексика по названию, тегам и словарю синонимов ru/kk/en.
5. **Ранжировать.** Веса: релевантность 0,45, близость 0,20, часы 0,15, популярность 0,10, полнота данных 0,05, погода 0,05. MMR (λ = 0,7) убирает однотипные места из топ-3.
6. **Написать текст** (`app/generate.py`). Claude получает кандидатов и пишет «почему» (не больше двух предложений) и «что делать». Запрос пользователя передаётся модели как данные, а не как инструкции. Место пользователя в промпт не попадает.

## Проверка (`app/validate.py`)
- Карточки с id не из списка кандидатов отбрасываются.
- Название, категория, расстояние, минуты пешком, часы и адрес берутся из данных.
- Фразы «открыто сейчас», «open now», «қазір ашық» вырезаются, если статус часов не open с уверенностью high.
- Одинаковых названий в ответе нет: безымянные места (их много среди 260 площадок) различаются подписью вроде «Детская площадка у Golpas».
- **Маршрут** (`app/route.py`, `app/walkgraph.py`) считается на нашем сервере по графу тротуаров и переходов OpenStreetMap (`data/processed/walk_graph.npz`: 60 820 узлов, 85 936 рёбер, 4075 переходов, из них 2207 со светофором; весь город, 9 из 9 плиток; снимки OSM 31.05–18.10.2026). В ответе: путь по тротуарам, метры и минуты по графу, переходы (светофор / зебра / без разметки) и лестницы (`path_source: graph`). Если отдельный отрезок по графу не строится (нет привязки или пути, крюк), только он считается по прямой × 1,3, маршрут остаётся по графу, а к `route.note` добавляется «Часть отрезков посчитана по прямой × 1,3». Если по графу не пошёл ни один отрезок или расчёт не уложился в лимит времени, весь маршрут считается по-старому: прямые отрезки × 1,3 при 4,5 км/ч (`path_source: straight`), и `route.note` об этом говорит. `WALK_GRAPH=false` выключает граф целиком. Наружу при расчёте маршрута ничего не уходит.
- **«Как пройти».** На карточке есть ссылки 2GIS и Яндекс Карты: браузер по клику открывает их пешеходный маршрут от точки старта до места. Это ссылка, а не источник данных (подробнее в ETHICS).

## Без LLM
Сбой, лимит, отказ, отсутствие ключа или `use_llm=false` дают один и тот же путь: запрос разбирают правила, карточки собираются по шаблонам из тех же кандидатов. В ответе это видно как `data_used.generation = "template"`. Проверяется сценарием E10 и полным прогоном `--no-llm`.

## После сдачи: волна 8 (ветка `wave-8`, не в `main`)
Принцип тот же: факты считает код. Сверено по `wave-8` e19d703 (правила — `docs/ARCHITECTURE.md` §5, «Подбор волны 8»).
- **Профиль маршрута** (`route_profile`). Его выбирает пользователь. Профиль меняет стоимость рёбер графа, но не данные.
  - «Без ступенек» (`accessible`). Лестницы запрещены. Переход без разметки +120 с, бордюр без данных +15 с, высокий +120 с. Если без лестниц пути нет или он длиннее больше чем на 30 %, маршрут идёт со ступенями, а причина записана в `route.note`. `overrides.wheelchair` при «Быстрее» включает этот профиль.
  - «По освещённым улицам» (`lit`). Ребро с lit=no ×3, без данных ×1,2.
  - Строка «маршрут: без ступенек / по освещённым улицам» в `filters` появляется, только если маршрут по графу действительно построен этим профилем.
- **Факты маршрута** (`MiniRoute` 1.3.0). Доли длины пути lit=yes / lit=no / нет данных, число переходов с занижённым бордюром и без данных, ступени, самый долгий отрезок пешком (`max_outdoor_leg_min`). У прямых отрезков освещённость 0 / 0 / 1, а бордюров нет (`None`). Переход без данных о разметке — `unknown` («переход»), а не «зебра».
- **Предпочтения** (`prefs`) входят в ранжирование, а не в фильтр.
  - Каждая метка из «Нравится» даёт +0,25 к скору (всего не больше +0,30).
  - Каждая метка из «Не хочу» даёт −0,25 (не больше −0,35).
  - Исключение — «без баров»: это фильтр, он убирает `bar` и `nightlife`.
  - В `filters`: «предпочтения: …; избегать: …».
- **«В тепле»** включается меткой `warm`, `overrides.indoor_only` или морозом ≤ −10 °C (Open-Meteo). Остановки берутся только в помещении, до каждой и между ними не больше 10 минут пешком, без петли. Если мест в помещении меньше двух, показываются уличные места с предупреждением.
- **«Ещё»** (`exclude_poi_ids`, до 9). Уже показанные места отсекаются до скоринга и до отбора Claude. В `filters` только число. Если других мест нет, так и пишем.
- **События** (`app/events.py`, `data/events.json`).
  - Кандидатами становятся события, которые ещё не закончились и начинаются сегодня или в ближайшие 6 ч. Фильтры те же, что для мест, плюс +0,08 к скору.
  - Без `ends_at` событие длится 2 ч, но не дольше полуночи своего дня.
  - «Идёт сейчас» — только при `starts_at ≤ сейчас < ends_at`.
  - Время визита берётся из события, а не от модели.
  - Пустой или битый файл событий означает, что событий нет; ошибки при этом нет.
  - Сейчас событий 0: источники ждут решения пользователя.

### Волна 8.1 (контракт 1.3.1, `w8-1-contract` 66a26ca)
Сверено по коду FEATURES `feat/w8-features` db0487b, CORE `feat/w8-core` b3c05c9; интерфейс (UX, T134) ещё в работе.
- **Словари prefs.** «Нравится»: `quiet`, `coffee`, `kids`, `museums`, `parks`, `warm`, `night`. «Не хочу»: `bars` (без `bar` и `nightlife`, вместо прежней `no_bars` в «Нравится»), `noisy`, `long_outdoor`, `kids_places`, `cafes` (без категории `cafe`, чип «Без кафе»). Противоречивые пары `kids` + `kids_places` и `coffee` + `cafes` → 422. Прежняя `no_bars` в «Нравится» читается как `bars` в «Не хочу» (синоним до 1.4).
- **Ночной профиль** `lit` — «Ночью — по крупным улицам» (в `filters`: «маршрут: ночью — по крупным улицам»): рёбра вдоль крупных улиц дешевле, lit=no дороже; имя `lit` в API оставлено для совместимости.
- **`straight_share`** — доля длины пути прямыми отрезками (0 — весь по графу, 1 — весь прямой). «Без ступенек» — только при графе, 0 ступеней и `straight_share = 0`.
- **Событие в маршруте** — только если начнётся не позже чем через 30 мин, и тогда последней остановкой (`plan_route(..., last_stop_id=…)`); иначе карточка остаётся, но не остановка. У события `venue` — название площадки.
- **Погода** — прогрев на сегодня при старте сервера, тайм-аут 1,5 с; не успели — ответ без погоды и строка в `data_used.weather`. В Open-Meteo уходит центр поиска с округлением до 0,1° (≈11 × 7 км).
