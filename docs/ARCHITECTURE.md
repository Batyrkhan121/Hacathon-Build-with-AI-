# Архитектура Qadam (ADR-002)

Статус: принято 18.10.2026. Заменяет ADR-001 (разделение на четыре роли): там работа шла по людям, здесь по параллельным сессиям Claude Code в worktree.
Владелец файла: интегратор.

## 1. Что оптимизируем
Порядок взят из критериев жюри (docs/TASK.md):
- **Релевантность.** Жёсткие фильтры (дистанция, часы, ограничения), затем ранжирование. Ответ даёт LLM, но только по найденным кандидатам.
- **Контекст.** Время, погода, бюджет времени, дети, доступная среда, ночь. Всё это явно передаётся в фильтры и в ответ.
- **Объяснения.** У каждой карточки есть «почему», «что делать», время, источник и уверенность.
- **UX.** Демо понятно с первого экрана: пресеты сценариев, карта, маршрут.
- **Этика.** Сервер получает только H3-ячейку, есть честные метки и запасной путь без LLM.
- **Завершённость.** Eval на 15 сценариях и документы, собранные из реального кода.

## 2. Решения и альтернативы

| # | Решение | Альтернативы | Почему так |
|---|---|---|---|
| D1 | Векторный индекс в памяти: numpy, косинус | Qdrant, pgvector, FAISS | В Астане ~2–5 тыс. POI, полный перебор занимает меньше 5 мс. Без инфраструктуры, работает на Windows и в Docker одинаково. Пересмотреть, если POI станет больше 100 тыс. или понадобится несколько инстансов. |
| D2 | Один сервис FastAPI отдаёт и API, и `web/` (чистый JS + Leaflet) | Streamlit; React/Vite | Настоящее веб-приложение, без сборщика, один деплой, полный контроль над UX. Streamlit выглядит шаблонно, React — лишний тулчейн на сутки. |
| D3 | Факты считает код, текст пишет LLM; валидатор и шаблонный запасной путь | Всё делает LLM | Нет галлюцинаций в расстояниях и часах. Демо не падает без квоты (критерии 1, 3, 6). |
| D4 | Приватность: в браузере координаты переводятся в H3 r9, сервер не принимает lat/lon (`extra="forbid"`, тест) | Округление координат; хранение с согласием | Минимизация по закону РК № 94-V. Это наглядно в демо: рисуем ячейку на карте. |
| D5 | Claude через `anthropic` SDK: `claude-sonnet-5-5`, запасная `claude-haiku-5-5`; structured output в Pydantic (`messages.parse`), дисковый кэш. Эмбеддинги — Gemini (google-genai), по желанию, только при `GEMINI_API_KEY` | Gemini для всего (прежняя версия D5); OpenAI; локальные модели | Решение команды 18.10: ключ Anthropic. У Anthropic нет API эмбеддингов, поэтому векторный индекс опционален, а без него retrieval лексический (запасной путь заложен в D1/D3). Модели задаются в .env, проверка — `scripts/check_env.py --llm`. |
| D6 | Основа — OSM (Overpass), плюс Wikidata; LLM-описания с пометкой | 2GIS, Google Places | Сбор автоматизирован, лицензия ODbL. 2GIS запрещает хранение. Google Places — опция позже. |
| D7 | Контракт до кода + дорожки в worktree + интегратор | Все правят всё; разбиение по людям | Параллельная работа без конфликтов, у каждого файла один владелец (§6). |

## 3. Поток RAG
```
браузер: запрос + (ориентир | GPS→H3 r9) + фильтры + время
   │  POST /api/recommend  (RecommendRequest: без координат)
   ▼
resolve_origin ─► parse_query (LLM ⟶ rules) ─► apply_overrides ─► QueryIntent
   │                                                     │
   ▼                                                     ▼
SearchContext: центр ячейки, местное время UTC+5, погода (Open-Meteo), radius_for(intent)
   │
   ▼
retrieve: жёсткие фильтры (дистанция, категории, дети, коляска, помещение, часы, ночь)
        → релевантность (cosine по эмбеддингам | лексика)
        → скор = Σ WEIGHTS × части → MMR-разнообразие → top-8 Candidate
   │
   ▼
draft_cards (Claude, JSON по схеме)  ── LLMUnavailable / use_llm=false ──► template_cards
   │
   ▼
finalize: id ∈ кандидаты, факты из Candidate, «открыто сейчас» только при open/high, метки
   │
   ▼
plan_route (≥2 карточки) ─► DataUsed + warnings + disclaimer ─► Answer (1–3 Card + MiniRoute)
```

## 5. Форматы данных
- `data/processed/poi.jsonl`: по одному `POI` на строку, UTF-8. Коммитится в git, чтобы во всех worktree были одни данные.
- `data/index/embeddings.npy` (float32, N×D, L2-норма), `ids.json` (тот же порядок), `meta.json` (`model`, `dim`, `count`, `created_at`, `doc_template`).
- `data/landmarks.json`: список `Landmark`. Координаты приблизительные, пока у записи `verified: false` (их сверяет DATA).
- `data/raw/`, `data/cache/`: не коммитятся.
- API:
  - `GET /api/health`;
  - `GET /api/landmarks`;
  - `GET /api/meta`;
  - `POST /api/recommend` → `Answer`, при неверном вводе 422.

## 6. Как работаем параллельно (Claude Code)
**Основа.** Контракт написан до кода (`schemas.py`, заглушки, фикстуры, мок `Answer`). Поэтому все дорожки стартуют одновременно и не ждут друг друга. У каждого файла один владелец (таблица в CLAUDE.md), значит при мерже почти нет конфликтов.

| Механизм Claude Code | Для чего у нас | Когда |
|---|---|---|
| **Десктоп: «+ New session» с галкой worktree** (Ctrl+N) | Длинные дорожки DATA, CORE, LLM, WEB, EVAL. Пользователь видит и направляет каждую. Worktree лежат в `.claude/worktrees/`. `.env` копируется через `.worktreeinclude`. | Волны 1 и 3 |
| **Субагенты с `isolation: worktree`** (`.claude/agents/*-engineer.md`) | Короткие независимые задачи на 15–40 мин из одного окна интегратора. Результат возвращается сводкой: ветка, коммиты, REQUEST. | Волна 3, мелкие доработки |
| **`/batch <инструкция>`** | Много однотипных мелких правок (i18n-строки, докстринги, типизация). Каждая правка в своём worktree. | По необходимости. Требует git и, для PR, GitHub-remote |
| **`/subtask`**, субагенты Explore | Побочные исследования (формат SDK, библиотека opening_hours) без засорения контекста. | Всегда |
| Agent teams (экспериментально) | **Не используем.** Участники команды работают без worktree, расход токенов выше, на Windows только in-process. | — |

**Ветки и база.**
- Основная папка всегда на `main`.
- `.claude/settings.json` → `worktree.baseRef: "head"`: новые worktree и субагенты ответвляются от локального `main`, даже если не всё запушено.
- Дорожки забирают обновления командой `git merge main`.
- В main вливает только интегратор: скилл `/integrate`, перед ним агент `merge-reviewer`.

**Ревью.**
- Встроенный `/code-review` проверяет дифф на баги.
- `/ecc:python-review` и `/ecc:fastapi-review` смотрят стиль и паттерны.
- `@agent-ecc:rag-pipeline-reviewer` проверяет качество RAG.
- `@agent-ecc:silent-failure-hunter` ищет проглоченные ошибки в запасных путях.
- `/security-review` запускаем перед публикацией (нужен origin).

## 7. Риски и что с ними делаем
| Риск | Что делаем |
|---|---|
| Лимиты, отказ (`refusal`) или недоступность Claude | Запасная модель (Haiku), server-side fallback, дисковый кэш пресетов, путь `use_llm=false`. Баланс API пополнить заранее. |
| Нет эмбеддингов (нет `GEMINI_API_KEY`) | Лексическая релевантность в retrieval; качество проверяем eval. Ключ Gemini можно добавить позже без изменения кода. |
| Неверные имена моделей или форма вызова SDK | `scripts/check_env.py --llm` и `scripts/check_llm.py` в первый же час, модели задаются в .env. |
| Overpass перегружен | Зеркала, повторы, кэш `data/raw/`, фикстур ≥ 40 POI (T10) в первые 40 минут. |
| Мало часов работы в OSM | Честное `unknown/low` и предупреждения. В слайде об ограничениях: план с партнёрскими данными. |
| Конфликты при мерже | Один владелец на файл, контракт меняет только интегратор, маленькие коммиты. |
| Нет времени на видео и слайды | EVAL-дорожка пишет документы параллельно с кодом. Код-фриз — утром 19.10. |
