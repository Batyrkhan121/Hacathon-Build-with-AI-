## Слайд 2. Qadam: 1–3 места с объяснением + live-демо S1 (1:30)

## Слайд 3. Как это работает: RAG, где факты считает код (0:50)

**Тезисы**
- Шесть шагов: понять запрос → контекст → фильтры → релевантность → ранжирование → текст.
- Расстояние, минуты пешком, часы и адрес считает код по данным. Claude пишет только «почему» и «что делать» про уже отобранные места.
- Данные: 1222 места OpenStreetMap по всей Астане, собираются одной командой. Описания от Claude есть у 3% мест и помечены.

**Что показать:** одна схема из [RAG.md](RAG.md):
```
запрос + район + время
  1 понять запрос (Claude → JSON; сбой → правила ru/kk/en)
  2 контекст: центр H3-ячейки, время UTC+5, погода
  3 фильтры: расстояние, часы, дети, коляска, ночь
  4 релевантность: эмбеддинги или лексика
  5 ранжирование: веса + разнообразие (MMR) → 8 кандидатов
  6 текст: Claude «почему / что делать»; сбой → шаблоны
  проверка → 1–3 карточки + маршрут
```

**Текст спикера**
> Внутри классический RAG, но с одним жёстким правилом: факты считает код. Сначала разбираем запрос. Потом берём контекст: район, местное время, погоду. Жёсткие фильтры отсекают дальнее, закрытое, бары, если вы с ребёнком. Ранжирование учитывает смысл запроса, близость, часы, погоду и следит, чтобы в тройке не было трёх одинаковых кафе. И только потом Claude получает восемь кандидатов и пишет человеческое объяснение. Цифры в карточку он не вписывает: их подставляет код. Данные — OpenStreetMap, 1222 места по всему городу, собираются одной командой.

## Слайд 4. Почему этому можно доверять (0:50)

**Тезисы**
- «Открыто сейчас» пишем только при надёжных данных. Валидатор вырезает такие фразы из текста ИИ, если часы не подтверждены.
- Без ИИ тоже работает: при сбое, лимите или выключенном Claude ответ собирается по шаблонам из тех же данных.
- 16 тестовых сценариев с автопроверками: 16/16 с Claude и 16/16 без него. Найденные eval ошибки (бары без часов ночью, далёкая карточка у аэропорта) исправлены до сдачи.

**Что показать:** таблица eval (S1–S5 и E1–E11, все зелёные; рядом «было 15/16 → стало 16/16») и пример карточки, где у текста ИИ стоит метка «Идея ИИ», а у фактов источник OSM.

**Текст спикера**
> Почему этому можно верить? Первое: метки. Каждая карточка говорит, откуда факты и откуда идея: из данных или от ИИ. Второе: валидатор. Если модель напишет «открыто сейчас», а часы не подтверждены, фраза будет удалена до того, как вы её увидите. Карточки с местами не из списка кандидатов тоже отбрасываются. Третье: запасной путь. Нет ключа, лимит, сбой — ответ всё равно строится по данным, просто текст шаблонный. И четвёртое: мы это меряем. 16 сценариев, включая ночь, коляску, казахский язык и попытку prompt-injection, проверяются автоматически: 16 из 16 и с Claude, и без него. И eval не для галочки: он поймал две настоящие ошибки — бары без часов в два часа ночи и место в 48 минутах пешком от аэропорта. Обе исправлены.

## Слайд 5. Приватность: сервер не знает, где вы (0:40)

**Тезисы**
- По кнопке «Моё место» браузер берёт точный GPS, переводит его в H3-ячейку r10 (≈1,8 га, ребро ≈76 м — примерно квартал) и отправляет на сервер только её. Точную позицию наш сервер не видит никогда. Сервер принимает только ячейку или ориентир; сырые координаты и ячейки мельче r10 отклоняются схемой (422) — это проверяют тест и eval.
- Поиск идёт от центра ячейки. Claude получает только подпись района, без ячейки и координат; Open-Meteo — центр поиска с точностью ≈1 км. История запросов не хранится, в логах нет связки «ячейка + текст». По клику «Как пройти» браузер сам, мимо нашего сервера, открывает 2GIS или Яндекс с вашей точной позицией — чтобы навигатор повёл от того места, где вы стоите. Только по вашему клику. Кому что уходит — в ETHICS.md.
- Закон РК «О персональных данных и их защите» № 94-V: собираем минимум.

**Что показать:** «Моё место» или «Указать на карте» → закрашенный шестиугольник ячейки r10 с подписью «Мы передаём только этот район ≈1,8 га». Затем в панели «Какие данные использованы» блок «Что ушло на сервер»: `"h3_cell": "…"`, координат нет.

**Текст спикера**
> Геолокация — персональные данные, и мы её минимизируем. Когда вы нажимаете «Моё место» или указываете точку на карте, браузер превращает её в шестиугольник размером примерно с квартал — около двух гектаров. На наш сервер уходит только этот шестиугольник, точную точку сервер не видит никогда. Сервер технически не принимает координаты: схема запроса их отвергает, клетки мельче тоже, и это проверяют тесты. Раз ячейка маленькая, тем важнее остальное: мы не храним историю и не связываем в логах ячейку с текстом запроса. Точная точка нужна только навигатору: по кнопке «Как пройти» браузер сам открывает 2GIS или Яндекс с ней — мимо нас и только когда вы нажали.

## Вопросы жюри (короткие ответы)
- **Где здесь RAG?** Retrieval — поиск по базе 1222 мест OSM: фильтры по расстоянию, часам и ограничениям, затем близость по смыслу (эмбеддинги) и по словам, ранжирование. Generation — Claude получает только найденных кандидатов и пишет «почему» и «что делать»; факты (метры, минуты, часы, адрес) подставляет код, проверка отбрасывает всё, чего нет в кандидатах.
- **Почему без Postgres?** 1222 места и индекс 1222 × 768 помещаются в память одного процесса: поиск — перебор на numpy за миллисекунды, без отдельной базы и её администрирования. Данные пересобираются одной командой из OSM. Если мест станет на порядки больше или понадобится несколько серверов — тогда отдельное хранилище.
- **Почему без логина?** Чтобы ничего не знать о пользователе: нет аккаунтов, нет истории запросов, на сервер приходит только ячейка ≈1,8 га или ориентир. Логин добавил бы персональные данные, которые продукту не нужны.

- **Освещённость.** У 97,1 % длины пешеходного графа Астаны в OpenStreetMap нет сведений об освещении: 5372,7 из 5532,5 км.

- **Карта пробелов** показывает это по 610 ячейкам ≈0,74 км²: где в OSM нет сведений. Есть и таблица по шести районам официального списка: освещённость неизвестна в каждом из них, у 90,8–99,4 % дорожек. Это пробелы в открытых данных, а не оценка района.
- **Призыв:**
  - **акимату и НИЦ Smart City** — открыть данные об уличном освещении, бордюрах и пандусах на переходах под открытой лицензией, чтобы их можно было внести в OpenStreetMap;
  - **жителям** — отметить в OpenStreetMap освещение, бордюр и часы работы у своего дома: на Android — StreetComplete, на iPhone — Every Door. Правка доступна всем картам на открытых данных, а в Qadam появится после пересборки данных.

**Текст спикера**
> Когда Qadam пишет «нет данных», это не его слабость, а честность. Посмотрите: у 97 процентов пешеходного графа Астаны в OpenStreetMap нет сведений об освещении. Бордюр неизвестен почти у всех переходов, доступность для коляски — почти у всех мест. Карта пробелов показывает, где именно в OSM нет сведений.
