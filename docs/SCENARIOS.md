# Тестовые сценарии и ограничения

16 сценариев: S1–S5 взяты из кейса, E1–E11 краевые. Входы и автопроверки лежат в [`eval/scenarios.yaml`](../eval/scenarios.yaml), раннер — [`eval/run_eval.py`](../eval/run_eval.py). Проверяются только поля ответа `Answer` (`app/schemas.py`), без ручной оценки.

```bash
python -m eval.run_eval --no-llm                     # в процессе, без Claude
python -m eval.run_eval --url http://localhost:8000  # живой API
python -m eval.run_eval --mock                       # проверка самого eval
```
Отчёт пишется в `eval/report.md` и `eval/report.json`.

В каждом ответе всегда проверяются и общие правила: ответ соответствует схеме; ранги, места и названия не повторяются; если статус часов unknown, уверенность не может быть high и нужна пометка «нет данных / проверьте»; в «why» не больше двух предложений; маршрут ведёт только в места из карточек.

**Результат 18.10** (свежий `main`, 1228 POI, лексический поиск без эмбеддингов): **15/16 без LLM** (`--no-llm`) и **15/16 с Claude** (`claude-sonnet-5-5`). Время ответа: с Claude медиана ≈6,5 с без кэша (4–10 с), в шаблонном режиме меньше 10 мс. Провалы:
- **E2 с Claude.** Claude добавляет к ночному запросу категории bar/nightlife и тег `night`. Ретривер считает этот тег признаком ночной работы, и в ответ попадают три бара без данных о часах. Без LLM ответ правильный: Ginza (до 06:00) и Дастаркан (24/7). Исправляет QUALITY (`app/retrieval.py`).
- **E11 без LLM.** Две карточки правильные (кафе в 4 и 6 минутах), но третья — площадка в 48 минутах пешком: радиус расширился по бюджету в 2 часа. Исправляет FEATURES.

Режим `--mock` даёт 3/16. Так и задумано: один и тот же мок-ответ не должен проходить сценарии на kk/en, ночь, 422 и шаблонный режим. Это показывает, что проверки действительно ловят ошибки.

## Ограничения и как мы с ними обходимся
| Ограничение | Как обходимся |
|---|---|
| **Неполные часы работы.** В OSM часы есть у 27% POI, у парков и площадок их нет совсем | Статус unknown с уверенностью low, пометка «нет данных о часах, проверьте перед визитом». Фразу «открыто сейчас» валидатор удаляет (E1) |
| **Временные мероприятия.** В OSM их нет | Не придумываем. **План:** `data/events.json` вручную, с источником, датами и меткой «временное» (T74) |
| **Закрытые и переехавшие места.** OSM может отставать | На карточке дата выгрузки и источник. Данные обновляются одной командой `python -m pipeline.run_all` |
| **Плотность данных.** На 18.10 есть 1228 POI по всей Астане, но плотность неравномерная: у центра сотни мест, у аэропорта 3 кафе | Если рядом мало вариантов, радиус поиска расширяется, и в ответе появляется предупреждение. Если мест нет совсем, честно говорим об этом вместо выдумки |
| **Доступность для коляски** указана у 5% POI | По умолчанию «не подтверждено» (E8) |
| **Безымянные площадки.** В OSM почти у всех 260 площадок нет имени | В карточке подпись по ближайшему месту («Детская площадка у Golpas»). Одинаковые названия ловит общий инвариант eval |
| **У аэропорта почти пусто.** В радиусе 2 км от NQZ 3 кафе | Пресет S4 стоит в центре (Байтерек) с предупреждением про выезд в аэропорт. Для «я уже в аэропорту» система честно отвечает, что рядом почти ничего нет (E11) |
| **Квоты и сбои LLM** | Запасная модель Haiku, дисковый кэш, шаблонные карточки без Claude (E10) |
| **Нет эмбеддингов без `GEMINI_API_KEY`** | Лексический поиск по названиям, тегам и синонимам ru/kk/en |
| **Маршрут приблизительный** | Прямые отрезки × 1,3 при скорости 4,5 км/ч. Об этом написано в `route.note`. Настоящего пешеходного роутинга нет |
| **Язык (eval)** | Казахский от русского отличаем эвристикой по алфавиту (буквы ә, ғ, қ, ң, ө, ұ, ү, һ, і). Короткий казахский текст без этих букв засчитается как ru |
