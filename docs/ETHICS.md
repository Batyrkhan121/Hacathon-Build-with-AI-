# Этика и приватность

## Локация и персональные данные
Закон РК «О персональных данных и их защите» № 94-V от 21.05.2013 требует собирать персональные данные только в нужном объёме. Точная геолокация может быть персональными данными, поэтому мы её минимизируем.

| Мера | Где это в коде |
|---|---|
| Сервер не принимает координаты: только H3-ячейку r9 (≈0,1 км²) или id ориентира | `LocationInput` в `app/schemas.py` (`extra="forbid"`, ровно одно поле), тест `tests/test_contract.py` |
| Координаты в ячейку переводит браузер, и только после нажатия «Моё место» с согласия браузера | **план:** `web/` (дорожка WEB, ещё не готово) |
| Поиск идёт от центра ячейки, а не от точки пользователя | `SearchContext.origin` |
| В промпт Claude место пользователя не передаётся | `app/generate.py` (ветка LLM) |
| Логи без связки «ячейка + текст запроса», история не хранится | правило в `app/api.py`; **план:** проверить при интеграции |

## Достоверность
- **Факты из данных.** Расстояние, время пешком, часы и адрес считает код по записи POI. Источник указан на карточке (`facts_sources`), дата выгрузки есть в данных (`fetched_at`).
- **Уверенность в часах работы.** Статус open, closed или unknown всегда идёт вместе с уверенностью high, medium или low. Непонятный формат часов даёт unknown. Часы есть только у 28% POI, поэтому чаще всего видна пометка «нет данных о часах, проверьте перед визитом».
- **Никакого «открыто сейчас» без надёжных данных.** Валидатор вырезает такие фразы, eval проверяет это в каждом сценарии.
- **Метка «Идея ИИ».** Текст, который модель придумала сверх данных, помечен `idea_source: generated`.
- **Prompt-injection.** Текст запроса передаётся модели как данные, ответ разбирается строго по схеме. Сценарий E5 проверяет, что системный промпт не утекает и посторонние рекомендации не появляются.
- **Работа без ИИ.** Если Claude недоступен, ответ всё равно собирается по данным (сценарий E10).

## Безопасность пользователя
- Ночью показываем только места, которые подтверждённо работают допоздна, и добавляем предупреждение (сценарии S5, E2).
- Бары и ночные клубы не показываем в запросах с ребёнком (S3, E4).
- Если доступность для коляски не указана в данных (так у 99% POI), пишем «не подтверждено», а не «доступно» (E8).

## Данные и лицензии
- OpenStreetMap: ODbL. Атрибуцию «© участники OpenStreetMap» показываем в ответе (`data_used.sources`). **План:** вывести её и в подвале карты.
- Wikidata: CC0. Open-Meteo: погода без ключа.
- Описания, написанные Claude, помечены `description_source: llm_generated`.
- 2GIS и Яндекс не используем: их оферты запрещают хранить данные.

## Ограничения и риски
| Риск | Что делаем |
|---|---|
| Данные OSM устаревают, часов мало | Дата выгрузки, честное unknown, обновление одной командой `pipeline.run_all` |
| Лимиты, отказы, таймауты Claude | Запасная модель Haiku, дисковый кэш, шаблонные карточки |
| Нет ключа Gemini, а значит и эмбеддингов | Лексический поиск. Качество меряем eval |
| Смещение к «популярным» местам | Вес популярности 0,10, она считается по полноте записи, а не по отзывам. Рейтингов в открытых данных нет |
| Временные мероприятия и закрытые места | В данных их нет. **План:** официальная афиша с меткой «временное» |
