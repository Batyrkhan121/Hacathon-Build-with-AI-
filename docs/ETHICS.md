# Этика и приватность

## Локация
Закон РК «О персональных данных и их защите» № 94-V от 21.05.2013 требует собирать только нужные данные. Точная геолокация может быть персональными данными, поэтому мы её минимизируем. С волны 7 (19.10) браузер берёт GPS с высокой точностью и отправляет на сервер ячейку H3 **r10**: ≈1,8 га в Астане, ребро ≈76 м, примерно квартал. Это точнее прежней r9 (≈13 га), поэтому ещё важнее, что история запросов не хранится и в логах нет связки «ячейка + текст запроса».

| Мера | Где в коде |
|---|---|
| Сервер принимает только H3-ячейку не мельче r10 или id ориентира. Ячейки мельче r10 и сырые координаты отклоняет схема запроса (HTTP 422) | `LocationInput` в `app/schemas.py` (`extra="forbid"`, `MAX_H3_RES`, ровно одно поле, контракт 1.2.0); тест `test_request_rejects_raw_coordinates`; пробы приватности в eval: ячейка r11 и lat/lon → 422 |

## Кому уходят данные
Сверено по коду 18.10 (`main` f734580); строка про «Как пройти» — 19.10 по правке WEB f39f940; размеры ячейки r10 — по контракту 1.2.0 (`main` 7410e14). Волна 7 сверена 19.10 по коду `main` 5518ed9: браузер переводит GPS в ячейку r10, точная точка остаётся в памяти страницы и попадает в ссылку 2GIS или Яндекс только по клику «Как пройти» и только при «Моё место»; подписи площади в интерфейсе и подпись района из API — в гектарах.

|---|---|---|---|

В каждом запросе стоит `provider.data_collection = "deny"`: OpenRouter не направляет запрос провайдерам, которые сохраняют данные или используют их для обучения. Для ориентира — его координаты, для «Указать на карте» — центр ячейки r10 из ответа сервера (`context.origin`) | Текст запроса, id ячейки. - **Не передаются третьим сторонам с нашего сервера:** H3-ячейка, сырые координаты (их у сервера нет) и история запросов. Ячейка используется только на нашем сервере, чтобы найти центр поиска. Наружу место уходит в двух случаях: с сервера в Open-Meteo — центр поиска с округлением до ≈1 км (ячейку по нему не восстановить); из браузера в 2GIS или Яндекс Карты — только если пользователь сам нажал «Как пройти», и тогда для «моего места» это точная позиция GPS, а для точки на карте — центр ячейки r10.
- **Что всё-таки косвенно говорит о месте.** Подпись района и расстояния до ближайших мест, которые получает Claude, позволяют примерно понять район, но не точку внутри ячейки.
- **Что хранится на сервере.** Дисковый кэш `data/cache/` с ответами модели и векторами запросов, ключ — хэш промпта. Ячейки в кэше нет, поле `raw_query` из ответа разбора вырезается (`REDACTED_FIELDS`). Отдельной истории запросов нет.
- **Эмбеддинги без сбора данных.** Векторы запросов и индекса (`data/index`, 1222 × 768) получены через OpenRouter с `data_collection: deny`. Прямого вызова Gemini API в рабочем режиме нет: при `EMBED_PROVIDER=openrouter` код ходит только в OpenRouter, а если тот недоступен, поиск идёт по словам. Прямой Gemini API (`EMBED_PROVIDER=gemini`) остался только как настройка; на бесплатном тарифе Google по своим условиям может использовать такие запросы для улучшения продуктов, поэтому в демо он не используется.

## Достоверность
- **Факты из данных.** Код считает расстояние, время пешком, часы и адрес по записи POI. На карточке указаны `facts_sources`, у записи есть дата `fetched_at`.
- **Часы с уверенностью** (`app/hours.py`). Статус open, closed или unknown всегда идёт с уверенностью high, medium или low. Нет данных или формат непонятен — пишем unknown/low и «проверьте перед визитом». Часы есть только у 28% мест, так что такая пометка встречается часто.
- **Никакого «открыто сейчас» без open/high.** Это правило валидатора, и eval проверяет его в каждом сценарии.
- **ИИ помечен.** На карточке `idea_source: generated`, у описаний `description_source: llm_generated`.
- **Prompt-injection.** Запрос передаётся модели как данные, ответ разбирается строго по схеме. Проверяет сценарий E5.
- **Нет данных — так и пишем.** Если доступность для коляски не указана (так у 95% мест), пишем «не подтверждено» (E8). Если рядом пусто, говорим об этом прямо (E11).

## Безопасность пользователя
- Ночью предупреждаем о безопасности и оставляем только места, которые подтверждённо открыты или работают допоздна/круглосуточно (S5, E2).
- С ребёнком не предлагаем бары и клубы (S3, E4).
- Если Claude недоступен, ответ всё равно собирается по данным (E10).

## Данные и лицензии
- OpenStreetMap: ODbL, атрибуция в `data_used.sources` и на карте. Wikidata: CC0. Open-Meteo: погода без ключа.
- **Для публикации.** `data/processed/poi.jsonl` — производная база данных OpenStreetMap под лицензией **ODbL 1.0**. Нужна атрибуция «© участники OpenStreetMap», и база (с нашими дополнениями) распространяется под той же лицензией (share-alike). Граф тротуаров `data/processed/walk_graph.npz` — тоже производная база OpenStreetMap под ODbL 1.0, с теми же условиями.

## После сдачи: волна 8 (ветка `wave-8`)
Всё в этом разделе есть только в ветке `wave-8`, не в сданной версии (`main`, тег `submission-2026-10-19`). Сверено по коду `wave-8` e19d703 и `data/processed/REPORT.md`; волны 8.1 и 8.2 — по контракту 1.3.1 и коду `wave-8` 730800c (CORE, FEATURES и UX влиты).

**Мои предпочтения (`prefs`).**
- Только метки из двух словарей (контракт 1.3.1): «Нравится» — тихо, кофе, с ребёнком, музеи, парки, в тепле, ночные (`LikeTag`); «Не хочу» — бары, шумно, долго на улице, детские места, кафе (`AvoidTag`). До 8 меток в каждом списке. Свободного текста нет.
- Хранятся только в браузере этого устройства: `localStorage`, ключ `qadam.prefs.v1`. Кнопка «Очистить» удаляет запись. Подпись в интерфейсе: «Хранится только в этом телефоне. С запросом уходят только метки, сервер их не сохраняет.»
- На сервер метки уходят с каждым запросом и живут только в нём. Сервер их не хранит, истории нет. В текстовом представлении запроса их нет (`repr=False`). В строке лога `recommend id=…` только счётчики.
- Неизвестная метка, метка из чужого списка (словари не пересекаются, так что «одна метка в обоих списках» — тот же случай), `no_bars` в «Не хочу», свободный текст, повтор, противоречивая пара («с ребёнком» + «детские места», «кофе» + «кафе»), лишнее поле (например, `history`) → 422 с фиксированным текстом «Неверный формат запроса.». Введённое в ответе не повторяется.
- Прежняя метка `no_bars` в «Нравится» (1.3.0) — синоним «Не хочу: бары», не 422 (решение Megah, 21.10; до версии 1.4).
- Проверки: 9 проб приватности eval → 422 без повтора ввода (r11, координаты, метка не из словаря, свободный текст, лишнее поле, обе противоречивые пары, метка из чужого списка, `no_bars` в «Не хочу»); проверка совместимости «`no_bars` в „Нравится“ → ответ и „избегать: бары“»; сценарий E18; в прогоне без сервера eval смотрит логи E15 и E17 (prefs не пишутся рядом с ориентиром и запросом); тест caplog у FEATURES.

**«Ещё» (`exclude_poi_ids`).** До 9 id мест, уже показанных в этой серии ответов, чтобы не повторять их. Живут в одном запросе: браузер их не сохраняет, новый запрос из формы серию сбрасывает. Сервер их не хранит и не логирует. В ответе только число: «без уже показанных мест: N».

**Освещённость, бордюры, ступени — данные OSM, а не обещание.** Ночной профиль называется «Ночью — по крупным улицам» (строка в `filters` «маршрут: ночью — по крупным улицам»): дешевле рёбра вдоль крупных улиц, lit=no дороже. Слово «освещённые» в его названии не используем: освещённость в OSM известна у 2,9 % длины пути. «Освещено» и «крупная улица» нигде не значат «безопасно»; eval проверяет, что в `route.note` нет слова «безопасно». Данных мало:

| По графу тротуаров (REPORT.md) | Есть данные | Нет данных |
|---|---|---|
| Освещённость, по длине | lit=yes 2,5 %, lit=no 0,4 % | 97,1 % |
| Бордюр на 4075 переходах | занижен 63, не занижен 8 | 4004 |
| Разметка переходов | светофор 1401, разметка 1133, без разметки 156 | 1385 («переход», не «зебра») |
| Доступность у 1222 POI | yes 42, limited 5, no 20 | 1155 |

Поэтому у маршрута показываем доли «освещено N % по данным OSM, нет данных M %» (с 1.3.1 только у ночного профиля) и число переходов без данных о бордюре. «Без ступенек» означает: лестниц нет на участках по графу; если часть пути посчитана по прямой, `route.note` говорит «На прямых отрезках ступени не проверены». С 1.3.1 «без ступенек» утверждается только при `straight_share = 0` (весь путь по графу); eval это проверяет.

**«В тепле».** Включается меткой «в тепле», фильтром «только в помещении» или морозом ≤ −10 °C по Open-Meteo. Это свойство мест, а не данные о человеке.

**Погода (волна 8.1).** В Open-Meteo уходит центр поиска, округлённый до 0,1° (≈11 × 7 км в Астане; в сданной версии было 2 знака, ≈1 км): одна погода на часть города, ни ячейку, ни точку по нему не восстановить. Сервер прогревает погоду на сегодня при старте и ждёт Open-Meteo не дольше 1,5 с; не успел — ответ без погоды и строка об этом в «Какие данные использованы». Погоду на живом API не подменяем: мороз на демо — только на моке.

**События.** Карточка `kind=event` и есть метка «временное». На ней только факты (название, площадка, адрес, время) и ссылка «Источник» (`source_url`, только https, открывается по клику). Источники — только из списка с проверенными условиями (`data/manual/event_sources.json`); 2GIS и Яндекс нельзя. «Идёт сейчас» пишем, только если запрос попадает между началом и концом. С 1.3.1 у события есть отдельное поле площадки (`venue`); событие становится остановкой маршрута, только если начнётся не позже чем через 30 мин, и тогда оно последнее. Источник подписан «Из афиши · домен». Источники волны 8.1 — официальные сайты площадок и организаторов и городские порталы; агрегаторы билетов пока не берём. **Сейчас список источников пуст и в `data/events.json` событий 0:** источники ждут решения пользователя. То есть живых событий пока нет; E16 проходит на тестовом файле eval: два тестовых события из `eval/fixtures/events_e16.json` (пометка «(тест)», источник example.org), только в eval, через `QADAM_EVENTS_PATH`.

## После сдачи: волна 9 — карта пробелов (ветка `wave-9`)
Сверено по контракту 1.4.0 (`wave-9` 36dd26e, `docs/ARCHITECTURE.md` §5). Файл карты (DATA T141), эндпоинт (FEATURES T142) и экран (UX T143) ещё в работе.
- **Только агрегаты открытых данных.** `data/processed/city_gaps.json` — счётчики по ячейкам H3 r8 (≈0,74 км²) и итоги по городу, посчитанные из OpenStreetMap (`poi.jsonl`, пешеходный граф): сколько мест, метров дорожек и переходов и у скольких из них нет сведений. В файле нет запросов, ячеек пользователей, списков мест и ничего о людях; лишние поля схема `CityGaps` отклоняет.
- **Эндпоинт ничего не принимает.** У `GET /api/city-gaps` нет параметров, ответ один для всех (`Cache-Control: public, max-age=3600`). Лишние параметры игнорируются: не меняют ответ и не попадают ни в ответ, ни в лог (в логе только путь, код и время). Проверка eval: запрос с ячейкой, координатами, текстом и метками в параметрах должен дать тот же ответ, что и без них, и ни одно из этих значений не должно быть в ответе и в логе.
- **Не оценка района.** Доля — «в OSM нет сведений», а не «плохо» или «опасно»; при малом числе мест, метров или переходов ячейка серая, «мало данных» (`GAP_MIN_*`).
- **Лицензия.** Карта — производная база OpenStreetMap под ODbL 1.0. В файле — `attribution` «© OpenStreetMap contributors», `license` ODbL-1.0 и ссылки на лицензию и на условия OSM; на экране — «© участники OpenStreetMap» (kk «© OpenStreetMap қатысушылары», en «© OpenStreetMap contributors») с теми же ссылками и датами данных (`poi_date`, `walk_graph_date`).

## Риски
| Риск | Что делаем |
|---|---|
| OSM устаревает, часов мало | Дата снимка, честное unknown, обновление одной командой |
| Лимиты и отказы Claude | Запасная модель Haiku, дисковый кэш, шаблоны |
| Нет эмбеддингов | Лексический поиск. Качество меряем eval в обоих режимах |
| Смещение к «популярным» | Популярность — прокси по полноте записи (вес 0,10). Отзывов и рейтингов в данных нет |
| Временные события и закрытые места | В данных их нет, поэтому ничего не придумываем. **План:** официальная афиша с меткой «временное» |
