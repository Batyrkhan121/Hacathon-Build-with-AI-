# Интеграция ветки в main

Аргумент: `$ARGUMENTS`
- `list`: только показать ветки и что в них нового.
- `all`: влить все готовые ветки по порядку data → core → llm → web → eval.
- `<ветка>`: влить одну ветку.

## 0. Предусловия (если не выполнены, остановись и скажи, что не так)
- `git branch --show-current` выдаёт `main`.
- `git status --porcelain` пустой.
- `.venv` есть.

## 1. Разведка
- `git worktree list` и `git branch --list`. Сопоставь ветки с дорожками по именам и по изменённым файлам.
- По каждой ветке-кандидату:
  - `git log --oneline main..<ветка>`;
  - `git diff --stat main...<ветка>`.
- Есть незакоммиченное в worktree дорожки (`git -C <путь> status --porcelain`)? Предупреди: это не вольётся. Попроси дорожку закоммитить.
- Для `list` на этом всё: выдай таблицу ветка | дорожка | коммитов | задачи (по сообщениям коммитов).

## 2. Ревью перед мержем
- Вызови агента `merge-reviewer`, передай ему имя ветки. Он вернёт PASS или BLOCK со списком.
- По таблице владения из CLAUDE.md проверь `git diff --name-only main...<ветка>`. Файлы интегратора (`app/schemas.py`, `CLAUDE.md`, `docs/PLAN.md`, `requirements.txt`, `.claude/**` и т. д.) из ветки не принимаем.

## 3. Мерж без коммита
- `git merge --no-ff --no-commit <ветка>`.
- Чужие или интеграторские файлы вернуть: `git checkout main -- <файл>`. Если правка нужна по сути, сделай её сам отдельным коммитом после мержа.
- Конфликты разрешай так, чтобы `app/schemas.py` из main оставался главным.

## 4. Проверки
- `.venv/Scripts/python -m pytest -q`
- `.venv/Scripts/python -m ruff check app pipeline eval scripts tests`
- Красное, и починка в 1–2 правки? Чини.
- Красное и сложнее? `git merge --abort`, верни дорожке конкретный список проблем (текстом для пользователя, чтобы он передал его в сессию дорожки).

## 5. Коммит и учёт
- `git commit -m "merge(<дорожка>): T.. T.. — <кратко>"`.
- Отметь задачи в `docs/PLAN.md` (`[x]` + одна строка заметки), затем `git commit -am "docs(plan): mark T.."`.
- REQUEST из отчёта дорожки (контракт, зависимость) выполни здесь, в main, отдельными коммитами. Новая зависимость: обнови `requirements.txt` и выполни `pip install -r requirements.txt` в своей `.venv`.

## 6. Отчёт пользователю (коротко)
- Что влито (коммиты, задачи), что отклонено и почему.
- Каким дорожкам выполнить `git merge main` и зачем. Например: «CORE и LLM: подтяните main — пришёл реальный фикстур poi_sample.jsonl».
- Следующий шаг по docs/PLAN.md.
