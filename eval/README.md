# eval: сценарии Qadam

22 сценария в `scenarios.yaml`: 16 из сдачи (S1–S5, E1–E11) и 6 волны 8 (E13–E18, `wave: 8`). Проверки — только по полям `Answer` (`app/schemas.py`). Подробности и результаты — `docs/SCENARIOS.md`.

## Запуск
Из корня репозитория:

```bash
.venv/Scripts/python -m eval.run_eval --no-llm --out <временная папка>   # в процессе, без Claude
.venv/Scripts/python -m eval.run_eval --out <временная папка>            # в процессе, с Claude (нужен .env)
.venv/Scripts/python -m eval.run_eval --url http://localhost:8010 --out <временная папка>
.venv/Scripts/python -m eval.run_eval --mock --out <временная папка>     # проверка самого eval
```

`--out` по умолчанию — `eval/`; `eval/report.*` в `.gitignore`, но отчёты лучше писать во временную папку. Ещё: `--only E13,E16`, `--note "..."`, `--smoke` (запросы команды из CSV без оценки).

## E16 и тестовые события
Решение пользователя (21.10): E16 идёт на тестовых событиях из `eval/fixtures/events_e16.json`, а `data/events.json` не трогаем. В фикстуре два события в «Астана Опера» 24.10 с пометкой «(тест)» и источником `https://example.org/eval-e16`: показ в 17:20 (через 20 мин после времени сценария — может быть остановкой, последней) и концерт в 19:30 (позже 30 мин — не остановка).

- **В процессе** eval сам ставит `QADAM_EVENTS_PATH` на фикстуру (и сбрасывает кэш настроек).
- **С `--url`** сервер нужно запустить с той же переменной, иначе у сервера событий нет и E16 не пройдёт; в отчёте об этом всегда есть строка:

  ```bash
  QADAM_EVENTS_PATH=eval/fixtures/events_e16.json .venv/Scripts/python -m uvicorn app.api:app --port 8010
  ```

## Проверки по локальным данным
Переходы «зебра» сверяются с `data/processed/walk_graph.npz`, площадки событий — с фикстурой событий. С `--url` у сервера могут быть другие данные, поэтому эти проверки выключены и в отчёте написано «не сверены»; `--local-data-check` (старое имя `--graph-check`) включает их, если данные те же.

## Что ещё проверяется вне сценариев
- **Пробы приватности** (9): ячейка мельче r10, сырые координаты, метки `prefs` не из словаря, свободный текст, лишнее поле, противоречивые пары, метка из чужого списка, `no_bars` в «Не хочу» — все должны дать 422, и с `--url` ответ не должен повторять ввод.
- **Совместимость**: `no_bars` в «Нравится» (1.3.0) — синоним «Не хочу: бары», ответ без 422 и «избегать: бары» в `filters`.
- **Логи** (только в процессе): prefs не пишутся в лог вместе с ячейкой, ориентиром или запросом.

Итог в отчёте делится на «основные 16» и «волна 8 из 6»: «основные» — те же 16 запросов, но с проверками волны 8, поэтому это не то же 16/16, что в README и PITCH сдачи.
