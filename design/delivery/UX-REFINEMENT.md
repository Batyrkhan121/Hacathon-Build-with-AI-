# Qadam · улучшение основного UX, версия 2

Задача пользователя: сделать существующий интерфейс красивее и удобнее. Изменены главный экран, результаты и переходы между ними. Работа остаётся в дизайнерском стенде `design/delivery/demo`; производственные `web/**` и `app/**` не изменены.

## Дизайн-решение

Основной визуальный ориентир — выбранный пользователем [Airbnb в Refero](https://styles.refero.design/style/c2325884-4391-4688-85cd-e143f5107517): светлые поверхности, выразительная типографика, небольшое количество рамок, акцент на поиске. Синий Qadam сохранён из принятой ранее палитры. Стандартная карта служит главным визуальным содержимым; фотографии объектов в контракте отсутствуют.

| Решение | Основание | Результат |
|---|---|---|
| Большой заголовок и единый блок запроса | Airbnb search-first, пользовательский сценарий прогулки | На старте ясно, что написать и куда нажать |
| Условия в одной раскрывающейся строке | Инструкция Батырхана, progressive disclosure | Ориентир, время и длительность видны; дополнительные поля открываются по необходимости |
| Белые карточки на светлом фоне без теней | Airbnb: разделение содержимого поверхностями и пространством | Карточки легче сравнивать |
| Название, минуты, часы и why снаружи | Решение о посещении и требования к достоверности | Важные сведения доступны сразу |
| What, адрес, теги, полнота и источники внутри «Подробнее» | Устранение перегрузки, поля существующего Card | Все данные сохранены, технические подробности не занимают первый экран |
| Синий — действие, маршрут и выделение | Существующая палитра Qadam | Зелёный остаётся только для open + high; ИИ — фиолетовый |
| Отдельный экран карты на телефоне | Основной путь: запрос → место → карта | Есть явный возврат к списку или выбранной карточке |

Вариант адаптирует плотность и порядок прежнего брифа: после названия сначала расстояние/время, затем источник идеи и часы. Этот порядок нужно перенести в production согласованно с POLISH; контракт API не меняется.

## Что изменилось

- Шапка компактнее, отметка «Демо» остаётся видимой на главной и в результате.
- После отправки форма действительно сворачивается в краткую строку запроса. Поведение одинаковое у живого preview и PNG; `capture=1` больше не меняет раскладку.
- Изменение условий показывает устаревший результат. Отмена редактирования восстанавливает отправленный запрос и параметры, а не оставляет черновик.
- Часы, неизвестное расписание, предупреждение о скором закрытии и источник идеи не спрятаны в деталях.
- Детали карточки и таймлайн маршрута раскрываются нативным `details`, работают с клавиатуры.
- На карте сохранены номера карточек, стандартные OSM-плитки, атрибуция и явное указание приблизительности маршрута.
- Выход с карты восстанавливает фокус; выход из выбора точки отменяет режим выбора. Отмена загрузки останавливает таймер и возвращает фокус в запрос.
- RU/EN больше не обещают «три идеи» при другом количестве карточек; локализованы новые элементы и адреса-примеры.

## Как посмотреть

Из `design/delivery` запустить `python3 -m http.server 5512 --bind 127.0.0.1`.

- `http://127.0.0.1:5512/demo/?view=home&lang=kk` — начать реальный путь по макету.
- `http://127.0.0.1:5512/index.html` — обновлённый каталог, PNG и кликабельный режим 360/390 px.
- `http://127.0.0.1:5512/overview.html` — обзор главного, ответа и desktop.

Это локальные ссылки: с другого устройства без дополнительной публикации они не откроются.

## Что передать разработчику

Основная разметка и стили — `demo/index.html`, `demo/polish.css`. Поведение стенда — `demo/preview.js`, новые тексты — `demo/lib/experience-copy.js`. Токены — `spec/tokens.json`.

Не копировать preview.js как серверный клиент: он работает с явными локальными примерами. При интеграции использовать реальный ответ API и снимок последнего отправленного запроса для сравнения условий. Не вычислять часы, источники и доступность на основании макета.

## Ограничения

Все ответы — fixtures. Настоящие модели, API, геопозиция и результаты QA-ветки Райымбека здесь не проверяются. Мок не рассчитывает новые рекомендации для произвольного текста, смены бюджета или даты. Состояния отказа геолокации и H3 показывают поведение интерфейса. Это не закрытие P1/P2 из `qa/security-audit`.

## Мобильные правки по отзывам команды

Убран вводный абзац на телефоне. Место, длительность и время вынесены в три подписанные кнопки, открывающие соответствующую настройку. Стрелки крупнее и контрастнее; сценарии выделены мягкими синим, янтарным и лиловым фонами. Desktop сохраняет прежнюю компоновку. Публичный макет: https://qadam-walks-prototype.nifty-buddy-6738.chatgpt.site.


### Анимация поиска

Внедрён вариант 03 из design/animation-lab: компактная пара следов над двумя skeleton-карточками. Подписи kk/ru/en. Анимация существует только в loading и удаляется вместе с ним при ответе/отмене. prefers-reduced-motion показывает статичные следы; skeleton не пульсирует. Текущий демонстрационный ответ по-прежнему приходит через 700 мс — дополнительного ожидания ради анимации нет. Изменены только дизайнерский прототип и статический SVG; для production интегратору перенести renderLoading, CSS, 3 строки каждого словаря и asset.


### Маленькие шаги на маршруте

На приблизительной линии добавлены декоративные следы, последовательно появляющиеся по направлению к местам. Leaflet-слой routeSteps находится ниже маркеров, не перехватывает нажатия и скрыт от screen reader. Размер следов фиксирован в экранных пикселях; при зуме/resize размещение пересчитывается, вокруг старта и мест оставлено 32px. На коротких отрезках следы не рисуются. При очистке ответа слой удаляется. Reduced motion оставляет статичный рисунок; это не live-геопозиция и не уточнение геометрии маршрута.


### Только следы между точками

По просьбе команды убран синий пунктир и белая подложка маршрута: между номерными метками видны только шаги. Геометрия остаётся невидимой для fitBounds; подпись о приблизительности сохранена. Проверены mobile/desktop, zoom, reduced motion, очистка слоя — без ошибок JavaScript.


### Сплошная линия со следами

Следы размещены по центру сплошного светло-синего маршрута 7px с белым контуром 11px. Соседние отпечатки отклоняются от оси на 1.5px; номера мест сохраняют свободную область. Цвет линии #9dbbe9, следов #245fc5. Пунктир отсутствует. Tooltip о приблизительном маршруте восстановлен; геометрия маршрута не изменена. Проверены mobile/desktop, zoom, загрузка asset, reduced motion и очистка следов; ошибок JavaScript нет.


### Более заметное направление шагов

Следы увеличены с 10×21 до 12×25px; минимальная opacity поднята с .18 до .45, reduced-motion .9. При последовательном появлении отпечаток смещается на 3px вдоль направления носка к следующей точке. Интервал 36px вместо 32px оставляет больше воздуха. Геометрия линии и нумерация мест сохранены. Проверены mobile/desktop, zoom (4 → 12 отпечатков), SVG, reduced motion, очистка слоя: без JS ошибок.


## Городской путеводитель · версия 3

Главная: крупный синий заголовок, одна форма с разделителями, жёлтая кнопка поиска; desktop форма/карта52/48. Результаты: общий бюджет и порядок остановок перед компактным списком, номера соединены линией, «Детали и источники» раскрывают поддерживающие сведения. Пользовательский запрос сохраняется при смене языка.

Новые стили city-home.css и city-results.css подключаются после polish.css. localize-answer.js переводит fixture-текст, не подменяя часы, числа, координаты и confidence. Макет по-прежнему использует локальные мок-данные и не подтверждает live API. Системные языковые подписи увеличены, доступное имя дополнительных параметров согласовано с видимой надписью.

Путь проверки: home → запрос/сценарий → полный план → детали → карта → возврат → изменение запроса. Шаги загрузки и шаги внутри сплошной линии карты сохранены.
