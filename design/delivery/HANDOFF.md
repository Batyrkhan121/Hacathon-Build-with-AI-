# Qadam · передача дизайна в POLISH

Обновлённый пакет UI/UX, версия 2. Изменения основного сценария описаны в `UX-REFINEMENT.md`. Основной язык — казахский. Ветка передачи: `codex/ux-ui-handoff`; источник интерфейса — локальный коммит `b1956ad`. Файлы `web/**`, `app/**`, данные и контракты проекта не изменены.

## Что передать Megah

1. `index.html` — каталог всех кадров; открывается локально без установки зависимостей.
2. `screens/` — PNG каждого состояния. Основные мобильные кадры 360×800, дополнительные 390×844 и 768×1000; desktop 1440×900, проверка 1280×720, видео 1920×1080.
3. `assets/` — исходный шестиугольный логотип Qadam и 18 SVG-иконок; системный шрифт без внешних сервисов.
4. `demo/` — интерактивный каталог состояний для проверки взаимодействия. Это дизайнерский стенд на локальных фикстурах, а не ветка production-вёрстки.
5. `CONTRACT-AND-COVERAGE.md` — соответствие полям и состояниям, запросы к POLISH / интегратору. `fixtures.json` — валидные демонстрационные ответы.
6. `spec/tokens.json` и кадр `30-styles.png` — цвета, размеры, интервалы и семантика статусов.

## Порядок вёрстки

Сначала кадры 01–02: главный и ответ. Затем 03–08: пять вариантов карточки и выделение с карты. Затем P0-состояния 09–13 и дополнительные ошибки 25–28. После этого маршрут / приватность / раскрытые данные 18–22, сценарии 14–17, desktop 31–33 и 39.

На главной — заголовок, единый блок запроса с условиями и пять сценариев в горизонтальной ленте. На телефоне условия разбиты на три явных поля: место, длительность и время; вводный абзац скрыт. После ответа форма сворачивается в строку с кнопкой изменения. Это живое поведение стенда, одинаковое для PNG и интерактивного режима.

В карточке видны название, время, статус часов, источник идеи и причина рекомендации. What, адрес, теги и подробные источники раскрываются в «Подробнее». Маршрут — отдельный раскрывающийся блок. На телефоне карта открывается отдельным экраном с возвратом к карточке. В desktop карта видна справа. Семантика статусов сохранена: green только open+high, POI нейтральный, ЖИ фиолетовый, medium контурный.

## Как проверить интерактивно

Из папки `delivery`:

```sh
python3 -m http.server 5512 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:5512/index.html`, выбрать состояние и размер. Сам экран: `http://127.0.0.1:5512/demo/?view=home&lang=kk`.

Пять сценариев запускают демонстрационные ответы. Есть раскрытие параметров, смена языка, устаревшие условия, повтор без ИИ, связь карточки с картой и выбор района как фиксированное состояние H3-фикстуры. Геолокация в стенде показывает разрешение / ошибку как состояние; настоящие координаты пользователя не запрашиваются. Сайт фиктивного POI отключён, чтобы не отправлять пользователя на `fixture.invalid`.

## Что макет не подтверждает

Статусы, часы, погода, время маршрута и тексты — синтетические примеры с пометкой «Мок-деректер». Они не являются проверкой реальных часов Alem.ai. Все карточки используют `facts_sources: ["mock"]`. Плитки карты — обычные OpenStreetMap, без цветовых фильтров, с атрибуцией.

Фиксированная дата — вторник 20.10.2026. «Завтра» от 18.10 — понедельник 19.10, поэтому в видео нельзя одновременно утверждать «завтра музей открыт» и «по понедельникам закрыт». Для демонстрации выбрать вторник явно либо уточнить дату записи.

После импорта PNG в Figma кадры сами по себе не станут кликабельными: переходы есть в `demo/`. Прямая запись через Figma MCP сейчас остановлена лимитом Starter. Ссылки на Figma Nearby/новый пакет не выдавались, потому что они не созданы.

## При интеграции

- id и `data-i18n` production не менять; новый текст — в `web/i18n.js` на трёх языках.
- Не переносить `demo/preview.js` как приложение: он только переключает фикстуры для дизайнерского ревью.
- Поля брать из `app/schemas.py`. `website` уже есть; минуты до закрытия / открытия отдельно в Card не передаются, только `open_note`.
- Закрыто + medium показывать «Жабық болуы мүмкін», не уверенное «Жабық».
- Запасной ответ должен менять `data_used.generation` на `template`; исходный production-мок этого пока не делает.
- Локальные UI-копии исправляют эти отображения только для стенда. Изменения приложения выполняет владелец POLISH по REQUEST.
- Один экран — один коммит POLISH, со скриншотами до и после; этот пакет сам не создаёт production-коммиты.

## Проверка

`manifest.json` содержит размеры, состояние, язык и границы первой карточки каждого кадра. Дополнительный независимый аудит — `QA-REVIEW.md`. PNG проверены визуально; 360/390/768/1280/1440 без горизонтального переполнения. Мок-карточки проверены по Pydantic-контракту. Живой API не запускался: это дизайнерская передача, интеграцию с сервером проверяет POLISH.


### Анимация поиска

Внедрён вариант 03 из design/animation-lab: компактная пара следов над двумя skeleton-карточками. Подписи kk/ru/en. Анимация существует только в loading и удаляется вместе с ним при ответе/отмене. prefers-reduced-motion показывает статичные следы; skeleton не пульсирует. Текущий демонстрационный ответ по-прежнему приходит через 700 мс — дополнительного ожидания ради анимации нет. Изменены только дизайнерский прототип и статический SVG; для production интегратору перенести renderLoading, CSS, 3 строки каждого словаря и asset.


### Маленькие шаги на маршруте

На приблизительной линии добавлены декоративные следы, последовательно появляющиеся по направлению к местам. Leaflet-слой routeSteps находится ниже маркеров, не перехватывает нажатия и скрыт от screen reader. Размер следов фиксирован в экранных пикселях; при зуме/resize размещение пересчитывается, вокруг старта и мест оставлено 32px. На коротких отрезках следы не рисуются. При очистке ответа слой удаляется. Reduced motion оставляет статичный рисунок; это не live-геопозиция и не уточнение геометрии маршрута.


## Городской путеводитель · версия 3

Главная: крупный синий заголовок, одна форма с разделителями, жёлтая кнопка поиска; desktop форма/карта52/48. Результаты: общий бюджет и порядок остановок перед компактным списком, номера соединены линией, «Детали и источники» раскрывают поддерживающие сведения. Пользовательский запрос сохраняется при смене языка.

Новые стили city-home.css и city-results.css подключаются после polish.css. localize-answer.js переводит fixture-текст, не подменяя часы, числа, координаты и confidence. Макет по-прежнему использует локальные мок-данные и не подтверждает live API. Системные языковые подписи увеличены, доступное имя дополнительных параметров согласовано с видимой надписью.

Путь проверки: home → запрос/сценарий → полный план → детали → карта → возврат → изменение запроса. Шаги загрузки и шаги внутри сплошной линии карты сохранены.
